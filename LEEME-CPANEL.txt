SEMIT — Despliegue en cPanel (Node.js)
=====================================

Contenido del zip (raíz = carpeta de la app Node en cPanel):
  app.js, package.json, package-lock.json, .env.example
  src/            código de la API
  data/           contenido del CMS en JSON (8 páginas)
  public/         frontend compilado + assets (imágenes)
  uploads/covers/ portadas de cursos del portal
  uploads/cms/    carpeta para imágenes subidas desde el CMS
  sql/            scripts de base de datos (opcional)

PASOS
1. cPanel → Setup Node.js App → crea app (Node 20+, startup file: app.js).
2. Sube semit-cpanel-node.zip a la carpeta de la app y extráelo ahí.
3. En terminal de la app:  npm install --omit=dev
4. Copia .env.example a .env y ajústalo:
     PORT=4000
     CORS_ORIGIN=https://semit.org,https://www.semit.org
     NODE_ENV=production
     ALLOW_OPEN_DEV=0
     ALLOW_LEGACY_HASH=0
     SYNC_ON_BOOT=0
     ADMIN_USER=admin
     ADMIN_PIN=tu-clave-larga-nueva (no reuses la de desarrollo)
     # SYNC_TOKEN=solo-si-lo-usas (autoriza writes, cuídalo como password)
     # MYSQL_URL=mysql://usuario:clave@localhost:3306/semit  (si usas BD)
     # Base del portal para sync de cursos (sin barra final)
     PORTAL_API_URL=https://aula-del-portal-real
     UPLOAD_IMAGE_MAX_MB=12
     UPLOAD_VIDEO_MAX_MB=100
     UPLOAD_JSON_MAX_MB=10
     SESSION_TTL_HOURS=72
   Si el aula virtual vive en otro dominio, ajusta también
   VITE_PORTAL_URL en el frontend antes del build (ver .env.production),
   o edítalo en /DirAdmin → Nav+Pie → Datos → Portal URL.
5. Reinicia la app (Restart) y abre https://semit.org/api/v1/health → {"ok":true}

SI LAS IMÁGENES DAN 500
El 500 en /assets/*.jpg con el HTML cargando = el hosting no entrega
los archivos estáticos. En este orden:
1. Abre https://semit.org/api/v1/diag → debe decir
   assets {ok:true}. Si dice ok:false, la carpeta public/assets/
   no se subió o quedó con otro nombre (mayúsculas, assets duplicado).
2. Permisos: archivos 644 · carpetas 755
   (click derecho en Administrador de archivos).
   Afecta a: public/assets/ y uploads/.
3. Borra o renombra cualquier .htaccess con reglas PHP viejas
   (php_flag, AddHandler, php_value) dentro de public_html/ o assets/.
4. cPanel → Hotlink Protection: desactívalo para tu dominio.
5. cPanel → Metrics → Errors: ahí sale la línea exacta del 500. Si dice
   "Permission denied" es paso 2; si dice "Invalid command 'php_flag'"
   es paso 3.
- Verifica directo: https://semit.org/assets/logo/logo.png debe dar 200.
- Imagen inexistente ahora da 404 (antes caía al index.html).
- El aviso [Intervention] de Edge sobre lazy-load es solo informativo,
  no causa el 500.

NO BORRES uploads/
- Al re-subir el zip, NO pises ni borres uploads/cms/ uploads/videos/ uploads/covers/ api/uploads/cms/ api/uploads/videos/ api/uploads/covers/: ahí viven las fotos/videos subidos desde el CMS.
- Sube solo: app.js, src/, data/*.json nuevos, public/ (frontend), sql/ si cambió.

NOTAS
- El frontend va servido por la misma app Node (public/index.html).
- data/*.json se puede respaldar/restaurar desde /DirAdmin → Respaldo.
- No subas tu .env real a ningún lado.
